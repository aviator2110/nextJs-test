# Тестовая работа №1
## Уроки 1–8: Next.js Fundamentals → Компоненты
 
**Продолжительность: 2 часа 20 минут (140 минут)**
 
---
 
## Формат
 
Практическое задание — собрать небольшое приложение с нуля (или на основе стартового шаблона, если преподаватель его выдал). Задание разбито на 6 частей, каждая проверяет материал определённых уроков. Ориентировочное время на часть указано рядом — можно распределять его по своему усмотрению внутри общего лимита в 140 минут.
 
**Каждый студент получает свой вариант** (домен предметной области) — таблица вариантов ниже. Структура задания у всех одинаковая, отличаются только названия сущностей.
 
| Вариант | Сущность | Поля сущности |
|---|---|---|

| B | Рецепт (Recipe) | `title`, `cookTimeMin`, `createdAt` |
 
Дальше в задании используется вариант A (Task) как пример — подставь название своей сущности из своего варианта везде, где встречается «Task»/«задача».
 
---
 
## Часть 1. Роутинг (~25 мин) — уроки 1, 3, 4
 
1. Создать страницу списка `/tasks` — вывести 4–5 задач-заглушек (захардкоженный массив с полями `id`, `title`, `done`, `createdAt`).
2. Создать динамическую страницу `/tasks/[id]` — открывать конкретную задачу по `id`.
3. Добавить `loading.tsx` для `/tasks` с искусственной задержкой в получении списка (хотя бы 1 секунда), чтобы `loading.tsx` реально было видно.
4. Добавить `not-found.tsx` для `/tasks/[id]` — вызывать `notFound()`, если `id` не существует в списке задач.
5. Разнести `/tasks` (список и деталь) и отдельную заглушку `/tasks/new` (страница создания — на этом этапе просто статичная разметка формы, без реальной логики) по **разным Route Groups** — убедиться, что итоговые URL не изменились.
 
---
 
## Часть 2. Композиция компонентов (~20 мин) — урок 8
 
1. Создать `TaskCard` — **Client Component** с `useState`, который показывает заголовок задачи всегда, а остальные детали — только по клику на кнопку «Подробнее».
2. Детали задачи должны рендериться как **Server Component**, переданный в `TaskCard` через `children` (не через прямой `import` серверного компонента внутри клиентского).
3. Дата создания задачи (`createdAt`) должна передаваться в любой Client Component как **строка**, а не как объект `Date`.
 
---
 
## Часть 3. Streaming (~15 мин) — урок 4
 
1. На странице `/tasks/[id]` добавить блок «Похожие задачи» — отдельный компонент с искусственной задержкой (1.5–2 секунды).
2. Обернуть этот блок в свой собственный `<Suspense>` с `fallback` — основной контент страницы (заголовок и детали задачи) должен появляться мгновенно, не дожидаясь этого блока.
 
---
 
## Часть 4. API Routes + защита (~30 мин) — уроки 5, 6
 
1. `app/api/tasks/route.ts` — `GET` возвращает список задач (в памяти сервера), `POST` добавляет новую задачу по `{ title: string }` из тела запроса, с валидацией (пустой `title` → `400`).
2. `app/api/tasks/[id]/route.ts` — `PUT` обновляет задачу по `id` (например, переключает `done`), `DELETE` удаляет задачу по `id`. Не забыть — `params` асинхронный, нужен `await`.
3. Создать/расширить `proxy.ts` — защитить **только** `POST`, `PUT`, `DELETE` для `/api/tasks` через заголовок `Authorization: Bearer <любой-токен>`; `GET` должен остаться полностью открытым.
4. Обернуть обработку тела запроса в `POST` в `try/catch`, чтобы невалидный JSON возвращал `400`, а не падал с `500`.
 
---
 
## Часть 5. Стилизация (~15 мин) — уроки 6, 7
 
Стилизация — **только Tailwind CSS**.
 
1. Добавить в `app/globals.css` кастомный цвет через `@theme` (например, `--color-brand`) и использовать его хотя бы в одном месте (`bg-brand`/`text-brand`).
2. Добавить переключение тёмной темы через класс `dark` на `<html>` — **не забыть** `@custom-variant dark (&:where(.dark, .dark *));` в `globals.css`, иначе `dark:`-классы не будут реагировать на класс.
3. Вынести кнопку (любую — например, «Подробнее» или «Добавить») в переиспользуемый компонент `app/components/Button.tsx` вместо копирования одной и той же строки классов.
 
---
 
## Часть 6. Данные и формы (~25 мин) — уроки 7, 9
 
1. Создать Server Action `addTask` (файл `actions.ts`, директива `"use server"`), валидирующий `title` через `zod` (непустая строка), возвращающий ошибку при невалидных данных.
2. Собрать форму добавления задачи на `/tasks/new` (место из Части 1) через `useActionState`, с выводом ошибки под полем и сообщением об успехе.
3. После успешного добавления вызвать `revalidatePath("/tasks")`, чтобы список обновился.
4. Где-нибудь на странице (например, «Статистика: выполнено X из Y») продемонстрировать осознанный выбор кеширования `fetch` — явно указать `{ cache: "force-cache" }` **или** `{ next: { revalidate: N } }`, с комментарием в коде, почему выбрано именно это значение.
